# ADR-001: v0.2 先完成纵向切片，不先造完整 DSL

- 状态：Accepted
- 日期：2026-08（v0.2 计划冻结）
- 相关：`docs/Nova-UI-v0.2-Editor-Foundation.md`

## 决策

1. **不先造完整 DSL。** 先验证 `UiNode`、稳定 `UiId`、`UiStateStore` 与真实 Avalonia 控件之间的关系。只有具体场景证明 DSL 有收益时才扩展。
2. **区分业务控件与高密度自绘控件。**
   - 表单、菜单、属性编辑器：Avalonia 标准控件 + 模板/样式。
   - Timeline、密集网格、节点图：在性能验证后自绘。
   - 3D 视口：通过 `IEngineViewportHost` 边界集成，UI Core 不依赖图形后端。
3. **先完成一条端到端链路，再扩充控件数量。**

## 理由

在基础控件、命令、撤销、布局尚未稳定时引入 DSL，会同时出现第二套布局、状态和调试系统，架构风险不可控。先做可运行切片能尽早暴露依赖方向和更新模型问题。

## 后果

- v0.2 的控制数量有限，但每个控制有明确 API、样式类、测试入口。
- `UiNode` 只是可测试的最小投影，不是运行时 UI 构建器。
- v0.3 才能评估 Dock 树；v0.4 才进入高密度自绘；v0.5 接入真实引擎视口。

## 约束

- 不允许在 v0.2 并行开发完整 Docking、Timeline、复杂 DSL、3D 后端。
- 前一版本架构门槛未通过，不把后续复杂功能叠加。
